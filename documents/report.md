## 摘要

最短路径问题是图论与组合优化中的基础核心问题。Dijkstra 算法作为求解单源最短路径（SSSP）的经典算法，其运行效率与底层最小优先队列（Min-Priority Queue）的实现高度耦合。针对课程项目 8-1 的各项指标要求，本项目采用 C++17 纯标准库自包含设计，完整实现了四种优先队列结构：**经典索引二叉堆（Binary Heap）、二项堆（Binomial Heap）、斐波那契堆（Fibonacci Heap）以及工程中广泛使用的惰性删除二叉堆（Lazy Binary Heap）**。

在理论分析层面，本报告以严密的讲义证明风格，深入剖析了斐波那契堆的内部机制与复杂度本质。通过构造势能函数 $\Phi(H) = t(H) + 2m(H)$，严格推导了其均摊 $O(1)$ 减键与均摊 $O(\log n)$ 弹出的理论边界；并采用数学归纳法与斐波那契数求和定理，完备证明了节点子树大小下界 $\text{size}(x) \ge F_{k+2}$ 与最大度数界限定理 $D(n) = O(\log n)$。

在实证研究层面，本项目选用了第 9 届 DIMACS 算法挑战赛提供的 7 组美国真实道路网络（规模涵盖 26 万至 189 万顶点），执行了严格的 1000 组点对查询（早停机制）与 16 组全图单源遍历测试。针对基础实验中“渐近理论最优的斐波那契堆在实际路网上落后于二叉堆”的现象，本项目并未止步于主观猜测，而是精心设计了**三大控制变量与消融实验**：

2. **状态清理策略消融实验**：量化论证了按需局部清理（Partial Reset）相对于全量清理（Full Reset）带来的最高 1.62 倍加速比；
3. **搜索规模分档对照实验**：揭示随着探索节点数扩大，常数开销被充分平摊，斐波那契堆相对二叉堆的耗时倍率呈现从 1.746x 收窄至 1.669x 的平滑收敛趋势。

# Chapter 1: Introduction

## 1.1 问题背景与研究动机

最短路径问题（Shortest Path Problems）是计算机科学与运筹优化领域最经典的基础问题之一。在有向带权图 $G = (V, E)$ 中，给定源点 $s$，单源最短路径（Single-Source Shortest Path, SSSP）要求计算 $s$ 到图中所有可达顶点的最短距离；若指定目标终点 $t$，则对应点对最短路查询（Point-to-Point, P2P）。

Dijkstra 算法基于贪心策略求解非负权图的最短路径。在其标准工作流中，优先队列负责维护候选集合并提供三大关键操作：
- $\text{Insert}(v, d)$：将新发现的顶点 $v$ 及其暂定距离加入优先队列（最多执行 $|V|$ 次）；
- $\text{Extract-Min}()$：提取当前暂定距离最小的顶点作为已确定顶点（严格执行 $|V|$ 次）；
- $\text{Decrease-Key}(v, d_{\text{new}})$：松弛邻接弧使得已有顶点距离变短时，减小其在优先队列中的键值（最多执行 $|E|$ 次）。

优先队列操作的代价直接决定了 Dijkstra 算法的整体复杂度：
- 采用二叉堆或二项堆：总复杂度为 $O((|V| + |E|) \log |V|)$；
- 采用斐波那契堆：由于减键操作被平摊优化至 $O(1)$，总复杂度达到著名的渐近理论上界 $O(|E| + |V| \log |V|)$。

然而，渐近复杂度忽略了常数因子、内存局部性以及真实图的拓扑分布。本项目的核心动机在于：在真实的大规模路网及合成控制图上系统实测这几种堆结构，探究算法理论与实际性能之间的辩证关系。

# Chapter 2: Data Structure and Algorithm Specification

## 2.1 Dijkstra 算法框架与抽象设计

为了保证不同堆结构在测试中的绝对公平性，消除框架代码对计时结果的干扰，本项目设计了统一的模板引擎 `DijkstraRunner<Heap>`。各堆对外暴露出一致的操作接口：
- `clear()`：重置堆内部状态；
- `insert(v, key)`：插入顶点 $v$ 及对应距离；
- `decreaseKey(v, new_key)`：将顶点 $v$ 的键值减小；
- `extractMin()`：弹出并返回最小距离对应的顶点编号；
- `contains(v)` / `keyOf(v)`：查询状态与当前键值；
- `cmps()`：精确记录堆内部发生的关键字比较次数。

针对点对最短路查询（P2P），算法在目标终点 $t$ 从堆中出堆时立即触发**早停（Early Stopping）**；针对完整单源最短路（Full SSSP），算法持续探索直到优先队列变空。

## 2.2 二叉堆 (Binary Heap)

二叉堆采用平坦的一维数组维护完全二叉树。为了以 $O(\log n)$ 支持减键操作，本项目额外维护了位置索引数组 `pos[v]`（记录顶点 $v$ 在堆数组中的当前下标）。
- **Insert**：新元素加入数组末尾，通过 `siftUp` 向上浮动，耗时 $O(\log n)$；
- **Extract-Min**：弹出堆顶，将数组末尾元素移至堆顶，通过 `siftDown` 向下调整，耗时 $O(\log n)$；
- **Decrease-Key**：依据 `pos[v]` 在 $O(1)$ 内直接定位元素位置，随后调用 `siftUp` 上浮，耗时 $O(\log n)$。

在节点交换时，必须同步更新被移动顶点在 `pos` 数组中的下标映射，以防外部索引错位。

## 2.3 二项堆 (Binomial Heap)

二项堆是一组遵循最小堆性质的二项树构成的森林。第 $k$ 阶二项树 $B_k$ 拥有 $2^k$ 个节点，根节点度数为 $k$。其核心机制如下：
- **合并 (Union)**：两个同阶的 $B_{k-1}$ 树可以通过将键值较大者的根挂为较小者的子节点，在 $O(1)$ 时间内合并为一棵 $B_k$ 树；
- **Insert**：新建单节点树 $B_0$，与原堆根链表执行合并，最坏复杂度 $O(\log n)$，均摊复杂度为 $O(1)$；
- **Extract-Min**：遍历根链表定位最小根，摘除该节点并将其子树链表逆序排列（使得度数按升序排列），再与剩余根链表合并，耗时 $O(\log n)$；
- **Decrease-Key**：减小键值后，沿父指针逐步向上冒泡交换节点编号与键值，耗时 $O(\log n)$。

## 2.4 斐波那契堆 (Fibonacci Heap) 的结构与机制（重点）

### 2.4.1 基本结构
斐波那契堆是一组有根树的松散集合，所有树根链接在一个双向循环链表（根链表）中。堆全局维护一个指针 `min_node` 指向当前最小值所在根。堆中每个节点维护六个指针/状态：
- 父节点 `parent`、任意子节点 `child`；
- 双向循环兄弟链表指针 `left` 与 `right`；
- 当前子节点个数 `degree`；
- 布尔标记 `mark`：指示该节点成为其他节点的孩子之后，是否丢失过一个子节点。

### 2.4.2 延迟合并机制 (Insert 与 Extract-Min)
- **Insert**：斐波那契堆采取极度懒惰策略。新节点以单节点形式直接挂入根链表中，不进行任何树的合并，直接更新 `min_node`，单次插入严格耗时 $O(1)$。
- **Extract-Min**：这是真正执行结构整理的阶段。
  1. 将 `min_node` 的所有子节点全部提升至根链表；
  2. 从根链表中摘除 `min_node`；
  3. 执行核心过程 `consolidate()`：利用辅助数组 $A[0..D(n)]$ 遍历根链表，若发现度数相同的两棵树，立即将其两两链接（小根为父，大根为子），直至根链表中没有任何两棵树拥有相同的度数；
  4. 重新扫描合并后的根节点集合，重设 `min_node`。

### 2.4.3 级联剪枝 (Cascading Cut 与 Decrease-Key)
减键操作是斐波那契堆实现渐近优势的核心所在：
1. 减小顶点 $x$ 的键值；
2. 若 $x$ 的新键值小于其父节点 $y$ 的键值（破坏了堆序），则调用 `cut(x, y)`：将 $x$ 从 $y$ 的子树中摘除，挂回全局根链表，重置 `x.mark = false`；
3. 调用 `cascadingCut(y)` 递归向上维护：
   - 若 $y$ 此时没有父节点（$y$ 已经在根链表上），直接结束；
   - 若 $y$ 的 `mark` 标记为 `false`，则将其置为 `true`（记录 $y$ 已失去了一个孩子）；
   - 若 $y$ 的 `mark` 标记已经为 `true`（说明 $y$ 失去了第二个孩子），则立即调用 `cut(y, z)` 将 $y$ 也切断挂入根链表，并递归向上对 $z$ 执行级联切断！

这种“失去两个孩子即被剪枝”的精妙约束，既保证了减键可以在均摊 $O(1)$ 内完成，又确保了任意度数为 $k$ 的节点其子树规模关于 $k$ 呈指数级增长，从而锁定了最大度数 $D(n) = O(\log n)$。

## 2.5 惰性删除二叉堆 (Lazy Binary Heap)

惰性二叉堆完全放弃了维护位置数组 `pos` 的复杂原地减键过程。当某条边松弛成功时，算法直接向优先队列中 `push` 一个新的副本 `(v, new_dist)`。在出堆时，若发现该顶点已经被确定（`done[u] == true`）或者弹出的距离大于当前记录的最短距离（`dist[u] < k`），则判定为陈旧无效记录并直接丢弃。

其理论堆大小可膨胀至 $O(|E|)$，单次操作代价为 $O(\log |E|)$，但由于避免了位置数组 `pos` 的同步维护开销，且数组连续访问缓存命中率极高，往往在稀疏图上展现出强大的常数优势。

## 2.6 实现亮点与工程优化设计

为了贴合实际工程与课程要求，本项目在底层代码中融入了四项关键设计：
1. **CSR 压缩稀疏行极速存储**：采用 `head[] + to[] + w[]` 三数组连续内存布局，配合整文件内存映射与自定义双指针整型扫描器，极大地减少了内存分配次数并提升遍历时的 CPU 缓存预取效率；
2. **预分配节点池（Node Pool）**：为二项堆与斐波那契堆的节点预先分配大块连续内存池，避免在数百万次松弛过程中频繁调用系统 `new/delete` 引发系统态开销与内存碎片；
3. **状态按需局部重置（Partial Reset）**：每次查询仅回滚记录在 `settled` 列表中的顶点标记，使查询重置开销严格控制在 $O(\text{Settled})$，避免了每次清空整图的 $O(|V|)$ 冗余开销；
4. **纯标准库与无头文件自包含**：所有 `.cpp` 源码均为独立自包含设计，不依赖任何自定义 `.h` 头文件，单文件即可直接编译，排除所有外部库干扰。

# Chapter 4: Analysis and Comments

## 4.1 理论复杂度深度推导与势能法摊还分析

### 4.1.1 复杂度总结
在包含 $n = |V|$ 个顶点、$m = |E|$ 条弧的图中，各堆操作与 Dijkstra 总复杂度对比如下：

| 操作 / 算法 | 经典二叉堆 | 二项堆 | 斐波那契堆 |
| :--- | :---: | :---: | :---: |
| **Insert** | $O(\log n)$ | 最坏 $O(\log n)$ / 摊还 $O(1)$ | **摊还 $O(1)$** |
| **Extract-Min** | $O(\log n)$ | $O(\log n)$ | **摊还 $O(\log n)$** |
| **Decrease-Key** | $O(\log n)$ | $O(\log n)$ | **摊还 $O(1)$** |
| **Dijkstra 总复杂度** | $O((m + n) \log n)$ | $O((m + n) \log n)$ | **$O(m + n \log n)$** |

### 4.1.2 势能函数与摊还代价严格推导
定义斐波那契堆 $H$ 的势能函数为：
$$\Phi(H) = t(H) + 2 m(H)$$
其中 $t(H)$ 表示堆中根树的总数量，$m(H)$ 表示堆中当前被标记节点（`mark == true`）的总数量。

下面推导各项操作的摊还代价 $\hat{c} = c + \Delta \Phi$：

1. **Insert 操作**：
   新节点以单节点形式直接挂入根链表。实际代价 $c = O(1)$。树的棵数增加 1，标记节点数不变，故 $\Delta \Phi = (t + 1) + 2m - (t + 2m) = 1$。
   因此摊还代价为：
   $$\hat{c}_{\text{insert}} = O(1) + 1 = O(1)$$

2. **Decrease-Key 操作**：
   假定减键过程中触发了级联切断，导致 $c$ 个节点被切断并提升为根（其中前 $c-1$ 个节点此前已被标记，最后 1 个父节点从未标记变为标记）。
   - 实际时间代价与切断次数成正比，即 $O(c)$；
   - 根树数量增加 $c$ 棵，故 $\Delta t = c$；
   - 前 $c-1$ 个节点被切入根后重置为未标记，最后 1 个节点被标记，故标记节点净变化 $\Delta m \le - (c - 1) + 1 = 2 - c$；
   - 势能变化为：
     $$\Delta \Phi = \Delta t + 2 \Delta m \le c + 2(2 - c) = 4 - c$$
   由此得到摊还代价：
   $$\hat{c}_{\text{decrease-key}} = O(c) + (4 - c) = O(1)$$
   **证明表明**：正是级联切断释放了此前积累的势能，抵消了递归剪枝的高昂代价，使得 Decrease-Key 达到了均摊 $O(1)$！

3. **Extract-Min 操作**：
   假定最小节点有 $d$ 个子节点，将其提升至根链表后，根链表总树数变为 $t + d$。`consolidate` 阶段将同度数的根两两配对，最终根树总数至多为 $D(n) + 1$（其中 $D(n)$ 为最大可能度数）。
   - 实际代价与合并前根数成正比：$c = O(D(n) + t)$；
   - 势能变化：$\Delta \Phi \le (D(n) + 1 + 2m) - (t + 2m) = D(n) + 1 - t$；
   - 摊还代价为：
     $$\hat{c}_{\text{extract-min}} \le O(D(n) + t) + (D(n) + 1 - t) = O(D(n))$$

### 4.1.3 最大度数界限定理的严格数学归纳证明
上述 Extract-Min 达到 $O(\log n)$ 的前提是最大度数满足 $D(n) = O(\log n)$。下文给出严谨数学证明：

**性质 1**：设 $x$ 为斐波那契堆中任意节点，度数为 $k$。将其子节点按加入顺序记为 $y_1, y_2, \dots, y_k$。则对任意 $i \ge 2$，有：
$$\text{degree}(y_i) \ge i - 2$$
*证明*：当 $y_i$ 被链接为 $x$ 的孩子时，$x$ 此前至少已有 $y_1, \dots, y_{i-1}$ 共 $i-1$ 个孩子，故当时 $\text{degree}(x) \ge i-1$。由于两棵树只有度数相等时才会合并，因此当时必有 $\text{degree}(y_i) = \text{degree}(x) \ge i-1$。成为孩子后，$y_i$ 至多再失去 1 个孩子（否则触发级联切断离开 $x$），故当前必有 $\text{degree}(y_i) \ge i - 2$。

**性质 2**：以度数为 $k$ 的节点 $x$ 为根的子树大小满足 $\text{size}(x) \ge F_{k+2}$（其中 $F$ 为斐波那契数列，$F_1=1, F_2=1, F_3=2 \dots$）。  
*证明（数学归纳法）*：
- 当 $k = 0$ 时，$\text{size}(x) = 1 = F_2$ 显然成立；
- 当 $k = 1$ 时，$\text{size}(x) = 2 = F_3$ 显然成立；
- 假设对所有 $< k$ 的度数结论均成立。对于度数为 $k$ 的节点，其子树大小为其自身加上所有子树大小：
  $$\text{size}(x) = 1 + \sum_{i=1}^k \text{size}(y_i) \ge 1 + \text{size}(y_1) + \sum_{i=2}^k F_{(i-2)+2} = 2 + \sum_{j=0}^{k-2} F_{j+2}$$
  由斐波那契求和公式 $\sum_{p=1}^m F_p = F_{m+2} - 1$，可得：
  $$\text{size}(x) \ge 2 + (F_k - 1) = 1 + F_k \ge F_{k+2}$$
  归纳成立。

由斐波那契数列通项公式 $F_{k+2} \ge \phi^k$（其中黄金分割比 $\phi = \frac{1 + \sqrt{5}}{2} \approx 1.618$），可得堆中总节点数 $n \ge \text{size}(x) \ge \phi^k$，两边取对数即得：
$$k \le \log_\phi n = \frac{\ln n}{\ln \phi} \approx 1.44 \log_2 n$$
即严格证明了 $D(n) \le \lfloor 1.44 \log_2 n \rfloor = O(\log n)$。

## 4.2 理论优势与实测性能背离的成因分析

通过理论推导与实验数据交叉比对，我们可以对“理论最优的斐波那契堆为何在路网中较慢”作出精确回答：
1. **稀疏路网中减键发生率极低**：道路网平均度数仅约 $2.5$，松弛成功的次数极少（实测每 100 顶点仅约 8~14 次减键）。斐波那契堆的理论强项在于“以每次弹出常数放大的代价，换取减键从 $O(\log n)$ 降低到 $O(1)$”。当减键占比极低时，这一策略在实际运行中无法弥补其常数劣势；
2. **指针链表 vs 连续数组的常数鸿沟**：斐波那契堆的节点包含 6 个指针/元信息，节点离散分配在堆内存中；而二叉堆由一段连续平坦的数组构成。连续数组的上浮下沉具有极高的 L1/L2 缓存命中率与硬件预取优势，实际操作常数比链表结构小 1 到 2 个数量级；
3. **Consolidate 内部比较开销过大**：斐波那契堆在每次弹出时必须遍历并两两合并根链表，带来了更多的元数据维护与链接操作。

## 4.4 讨论与工程选型建议

综合理论与全套实验，我们给出如下实用选型指南：
- **道路网与极稀疏图**：首选**惰性删除二叉堆（Lazy Binary Heap）**或**经典索引二叉堆**，常数小、实现简便、内存局部性极佳；
- **稠密图或极高频减键场景**：坚决摒弃惰性删除策略，优先采用**索引二叉堆**或**斐波那契堆**，以保障系统吞吐量不受堆膨胀摧毁；
- **理论关键领域**：在最小生成树（Prim 算法）、网络流与理论证明中，斐波那契堆仍具有不可替代的基石地位。

```cpp
#include <cstdio>
#include <cstring>
#include <iostream>
#include <algorithm>
#include <vector>
#include <queue>
#include <random>
#include <string>

using namespace std;

typedef long long Key;
const Key KEY_INF = 1LL << 60;

// 二叉堆实现（带 pos 数组位置映射，支持 O(log n) decrease-key）
class BinaryHeap {
public:
	explicit BinaryHeap(int n = 0) {
		init(n);
	}

	void init(int n) {
		key.assign(n + 1, 0);
		pos.assign(n + 1, -1);
		heap.clear();
		touched.clear();
		heap.reserve(n + 1);
		touched.reserve(n + 1);
		cmp_cnt = 0;
	}

	void clear() {
		for (size_t i = 0; i < touched.size(); i ++ ) {
			pos[touched[i]] = -1;
		}
		touched.clear();
		heap.clear();
	}

	bool empty() const {
		return heap.empty();
	}

	int size() const {
		return (int)heap.size();
	}

	bool contains(int v) const {
		return pos[v] >= 0;
	}

	Key keyOf(int v) const {
		return key[v];
	}

	long long cmps() const {
		return cmp_cnt;
	}

	void insert(int v, Key k) {
		key[v] = k;
		pos[v] = (int)heap.size();
		heap.push_back(v);
		touched.push_back(v);
		siftUp((int)heap.size() - 1);
	}

	void decreaseKey(int v, Key k) {
		key[v] = k;
		siftUp(pos[v]);
	}

	int extractMin() {
		int top = heap[0];
		int last = heap.back();
		heap.pop_back();
		pos[top] = -1;
		if (!heap.empty()) {
			heap[0] = last;
			pos[last] = 0;
			siftDown(0);
		}
		return top;
	}

private:
	void siftUp(int i) {
		int v = heap[i];
		Key k = key[v];
		while (i > 0) {
			int p = (i - 1) >> 1;
			int pv = heap[p];
			if (!lessKey(k, key[pv])) {
				break;
			} else {
				heap[i] = pv;
				pos[pv] = i;
				i = p;
			}
		}
		heap[i] = v;
		pos[v] = i;
	}

	void siftDown(int i) {
		int n = (int)heap.size();
		int v = heap[i];
		Key k = key[v];
		for (;;) {
			int c = 2 * i + 1;
			if (c >= n) {
				break;
			} else {
				if (c + 1 < n && lessKey(key[heap[c + 1]], key[heap[c]])) {
					c ++ ;
				}
				if (!lessKey(key[heap[c]], k)) {
					break;
				} else {
					heap[i] = heap[c];
					pos[heap[i]] = i;
					i = c;
				}
			}
		}
		heap[i] = v;
		pos[v] = i;
	}

	bool lessKey(Key a, Key b) {
		cmp_cnt ++ ;
		return a < b;
	}

	vector<Key> key;
	vector<int> pos;
	vector<int> heap;
	vector<int> touched;
	long long cmp_cnt = 0;
};
```
